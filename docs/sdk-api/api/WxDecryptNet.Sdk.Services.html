    VoiceAsr

    本地语音转写（ASR）后台队列。

    设计约束（与 hot-sync 链路解耦）：

    • 只在**增量**轮次入队：首轮同步不转写，避免拖慢首轮（见 DecryptAfterUpsert(allowVoiceAsr)）；
    • 入队只是 TryWrite(T)，永不阻塞读取/UPSERT/水位推进；
    • 转写在独立后台线程（BelowNormal、单并发）执行，异常全部吞掉并记日志；
    • 只回写 wechat_message.Content 一列，失败保持 [语音]，不重试、不改其他字段。

    模型由用户自行下载：Config 的 AsrModelDir 下放 model.int8.onnx（或 model.onnx）与 tokens.txt。 模型缺失/加载失败时本模块静默禁用，不影响 SDK 任何其他功能。

    WeChatAccountHotSyncEngine

    单账号后台同步引擎：加密库 → 旁路一致拷贝 staging → SQLCipher 直读 → 水位增量 UPSERT 中间表。 每个 WeChatClient / 账号应持有独立实例（独立 staging 与 WeChatDatabase 生命周期）。 只读微信侧，绝不写回原生库。SQLCipher 连接必须在再次拷贝 staging 之前 Dispose。

    WeChatHotSyncEngineOptions

    单账号 hot-sync 引擎可选项。

    WeChatMessageContentParser

    引用消息（原生 local_type = 244813135921，即 49 + (57 << 32)）的 appmsg/refermsg 解析器。

    解析规则： 外层 <title> 是回复文字，<refermsg> 里是被引用内容；

    被引用内容按 refermsg/type 转成 [图片] / [表情] / [视频] / [语音] / [链接] ...， 嵌套引用（type=57）递归取内层 title/des/content。

    微信 XML 可能存在未转义字符，故使用正则而不是 XDocument。

    另有 NormalizeForStorage(string?, long)：把非引用 appmsg / 媒体消息的 Content 归一化成可读文本。 当前 4.x 的 appmsg 标题/URL/recorditem 只在 message_content XML；表情的 desc 可能是 base64 protobuf（本类会解码，优先 zh_cn）。packed_info_data 的 protobuf 只承载媒体 md5 / 语音转写等，媒体 md5 仍由 WeChatMessageMediaSync 在归一化之前读取。

    WeChatMiddleDatabase

    中间表（SqlSugar）辅助：建库建表、水位查询、联系人/消息/群成员/朋友圈 UPSERT。 统一读写 Config 的 DbTppe + ConnectionString。

    WeChatNormalizedContent

    写库前的 Content 归一化结果。只覆盖 Content（以及聊天记录的完整 RecordItem）， 其它列（MessageType / FilePath / Quote* 等）由调用方保持原值。

    WeChatParsedQuote

    引用消息解析结果。写库时 Content 用回复文字，其余字段落到 wechat_message 的 Quote* 列。
