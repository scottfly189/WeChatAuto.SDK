微信消息中间表。UIA 监听与 Database Read 共用；支持多微信聚合。 对照原生 message_0/1/2.db 的 Msg_（各表同构）：差异同步业务键为 FromWechatWxId + ChatUsername + Shard + LocalId（ServerId 作辅助，不建外键）。 本机有 89 个会话跨 message_0/1/2，且各分片 local_id 都从 1 计，业务键必须带 Shard。 增量水位用 SortSeq：跨分片区间不重叠，按 FromWechatWxId + ChatUsername + Shard 取 MAX(SortSeq) 即可。 server_id / sort_seq / local_type 等会超过 Int32，C# 用 long 承接； 列类型显式声明 INTEGER（SQLite 的 INTEGER 最多 8 字节，可存 64 位）。 不要改成 C# int，也不要让 SqlSugar 默认映射成 BIGINT。 自增主键仍必须是 int：SqlSugar 把 long 主键映成 BIGINT，SQLite 不允许 AUTOINCREMENT。 UIA 写入时这些原生键可为空或 0，故先不加唯一约束，避免和旧行冲突。 发送者 username 在本分片 Name2Id.rowid = real_sender_id 解析后写入 SenderWxId， 不要跨分片使用 rowid。message_content 若被 WCDB 标成 zstd，写入前先解码； 群聊正文常见「sender_wxid:\n正文」，发送者进 SenderWxId，正文进 Content。 引用消息（local_type=244813135921）Content 只存回复文字，被引用内容在 Quote 列。 packed_info_data / source / compress_content 不镜像进本表。
