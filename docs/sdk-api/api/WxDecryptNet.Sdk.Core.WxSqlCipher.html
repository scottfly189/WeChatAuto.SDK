    DecodeMessageText(object?)

    Cell-value overload for ADO.NET / Microsoft.Data.Sqlite readers. WeChat columns such as message_content are mixed-type: TEXT cells come back as string, BLOB (zstd) cells as byte[]. Passing reader["col"] as byte[] silently turns TEXT rows into null (and the byte[] overload then returns ""). Prefer DecodeMessageText(reader["col"]) so both shapes dispatch correctly.

    OpenWeChatDb(string, byte[], string?, bool, int, bool, bool)

    Open a WeChat 4.x encrypted DB via SQLCipher. Tries passphrase first (WeChat 4.x uses a binary passphrase + cipher_compatibility=4), then raw, each with cipher_compatibility=4 and with the library default. Default open mode is ReadOnly with pooling off so Dispose releases the file lock; pass readWrite to opt into writes on a staging copy.

    Declaration
    public static SqliteConnection OpenWeChatDb(string path, byte[] keyBytes, string? mode = null, bool readWrite = false, int busyTimeoutMs = 0, bool deleteSidecarOnOpen = true, bool lightweightValidation = false)
    Parameters
    Type Name Description
    string path

    数据库路径；live 模式就是微信 db_storage 下的源文件。
    byte[] keyBytes

    32 字节密钥。
    string mode

    passphrase/raw/null（自动尝试）。
    bool readWrite

    只对 staging 副本传 true；live 源库必须只读。
    int busyTimeoutMs

    大于 0 时设置 PRAGMA busy_timeout；live 源库用它给微信写入/checkpoint 让路。
    bool deleteSidecarOnOpen

    是否在尝试 key 前删除同目录 -shm。live 源库必须传 false， 否则会删掉微信正在使用的 -shm。
    bool lightweightValidation

    用 SELECT 1 FROM sqlite_master LIMIT 1 代替 count(*) 验证 key， 避免 3 万+ schema 对象的大库每次打开都全扫。

    QuickCheck(SqliteConnection)

    对已打开的库执行 PRAGMA quick_check，返回结果行。

    正常只有一个 ok；出现其它文本表示页/索引损坏（SQLite 会把损坏信息逐条列出）。

    用途：SQLCipher 的逐页 HMAC 只能证明单页完整，证明不了「各页属于同一时刻」—— 微信 checkpoint 就地改写主库页时，一致拷贝仍可能拿到撕裂快照，此时必须靠整库校验兜底。
