    Class WeChatDecryptor

    数据库解密门面：把微信 4.x（SQLCipher / WCDB）的加密数据库解密成普通 SQLite。

    覆盖三种粒度：单库解密（DecryptFile(DecryptFileOptions)）、整账号批量解密（DecryptAll(DecryptAllOptions)）、 以及不落盘只验密钥（Verify(VerifyKeyOptions)）和列出待解库（ListDatabases(string)）。

    所有方法只读源库、只写 --out 指定的输出目录；不会修改微信自己的 db_storage。

    DecryptAll(DecryptAllOptions)

    解密整个账号：把 db_storage 下所有可解密的库批量解到输出目录。

    Declaration
    public static DecryptAllResult DecryptAll(DecryptAllOptions options)
    Parameters
    Type Name Description
    DecryptAllOptions options

    DecryptAllOptions：

    • Path：账号路径（规则同 ListDatabases(string)，必填）；
    • Key：32 字节密钥（必填）；
    • OutputDir：输出根目录（必填），其下自动建 <账号名> 子目录；
    • Flat：true 时不保留 message/ 等子目录，全部平铺（重名自动加 __1）；
    • Jobs：多文件并行度，0 表示自动（min(CPU/2, 8)）；每个库都需要一次独立的 PBKDF2（salt 不同），所以并行是整账号提速的主要来源；
    • SkipExisting：目标已存在则跳过，适合增量重跑；
    • Progress：进度回调 (已完成, 总数, 源路径, 是否成功, 失败原因)，可能来自多个线程。
    Returns
    Type Description
    DecryptAllResult

    DecryptAllResult：Status 为 success/partial/error； Total/Success/Failed 为计数；Jobs 实际并行度； Files 为逐文件明细（含 Skipped、FailedPages、ElapsedMs 等）。
    Remarks

    单个文件失败不会中断整批：结果里 Failed > 0、Status 变为 partial。 并行时每个文件内部强制使用 1 个页线程，避免 Jobs × 页线程 的线程超订。

    Exceptions
    Type Condition
    ArgumentNullException

    options 为 null。
    InvalidOperationException

    开跑前用探针库校验密钥失败（密钥不属于该账号）时抛出——这是"快速失败"，避免每个文件都失败一遍。
    FileNotFoundException

    路径不存在或找不到 db_storage。

    DecryptFile(DecryptFileOptions)

    解密单个数据库（SQLCipher 页解密 + WAL 合并 + SQLite 健康检查 + 原子落盘）。

    Declaration
    public static DecryptFileResult DecryptFile(DecryptFileOptions options)
    Parameters
    Type Name Description
    DecryptFileOptions options

    DecryptFileOptions：

    • SourcePath：源库路径（必填，只读）；
    • Key：32 字节密钥（必填）；
    • OutputPath：输出文件；为空时写到当前目录的 <源文件名>.plain.db；
    • InMemory：改用"整库读入内存"的参考实现（默认走流式，内存占用恒定）；
    • PageWorkers：单库内按页并行度，0 表示自动（小于 32 MB 用 1，否则 min(CPU/2, 4)）；
    • SkipQuickCheck：跳过最终 PRAGMA quick_check，仅供合成数据/基准测试，生产不要开。
    Returns
    Type Description
    DecryptFileResult

    DecryptFileResult：优先看 Success；失败时读 Error（密钥不匹配、 源库在读取期间被改动、存在待恢复的 -journal、输出未通过 SQLite 校验等）。 其余常用字段：KeyMode（raw/passphrase）、CopiedAsSqlite（源库本为明文，仅复制）、 TotalPages/FailedPages（失败页数，>0 即整体失败）、 HmacWarningPages（非首页 HMAC 异常但内容仍保留的页数，通常无碍）、 ElapsedMs（本文件耗时）。
    Remarks

    密钥错误、文件不足一页、源库被改动等都属于"可预期失败"，通过返回值报告而**不抛异常**， 调用方判断 Success 即可。

    写入流程：同目录临时文件 → quick_check（必要时只重建受损索引）→ 原子替换； 校验不通过会删除临时文件，不会产出半成品，也不会覆盖源库。

    Exceptions
    Type Condition
    ArgumentNullException

    options 为 null。

    ListDatabases(string)

    列出某个账号下会被解密的 *.db 文件（绝对路径，按路径不区分大小写升序）。

    Declaration
    public static List<string> ListDatabases(string path)
    Parameters
    Type Name Description
    string path

    账号路径，支持四种写法：

    • ...\xwechat_files\<wxid>\db_storage（推荐，直接命中）
    • ...\xwechat_files\<wxid>（wxid 账号目录，自动向下找 db_storage）
    • db_storage 下的子目录（如 ...\db_storage\message，自动向上找）
    • ...\xwechat_files 数据根目录（仅当其中恰好一个账号带 db_storage 时可用）
    Returns
    Type Description
    List<string>

    可解密数据库的绝对路径列表。会自动跳过：key_info.db、chat_search_index*.db、 以 _fts.db 结尾的索引库，以及所有非 .db 文件。
    Remarks

    只做目录遍历与文件属性读取，不打开数据库，速度很快，适合先"看一眼要解什么"。

    Exceptions
    Type Condition
    FileNotFoundException

    路径不存在，或无法从该路径定位 db_storage。

    Verify(VerifyKeyOptions)

    校验一枚密钥是否属于该账号：只读一个"探针库"的第一页做 HMAC 校验，不写任何文件。

    Declaration
    public static VerifyKeyResult Verify(VerifyKeyOptions options)
    Parameters
    Type Name Description
    VerifyKeyOptions options

    见 VerifyKeyOptions：Path（账号路径，规则同 ListDatabases(string)） 与 Key（32 字节密钥）均为必填。
    Returns
    Type Description
    VerifyKeyResult

    VerifyKeyResult：

    • Valid：密钥是否通过；
    • Reason：失败原因，key_mismatch 表示密钥不属于该账号， no_probe_database 表示目录里没有可用探针，read_error: … 表示读探针失败；
    • KeyMode：命中的密钥形态（raw 或 passphrase，明文库为空）；
    • Probe/DbStorage：实际探测的文件与账号目录。
    Remarks

    探针优先级为 msg0.db → msg.db → micromsg.db → favorite.db → mediamsg0.db → sns.db（取第一个 ≥4 KB 的库）。 只想确认密钥对不对时优先用本方法，比 DecryptFile(DecryptFileOptions) 快几个数量级。

    options 为 null。
